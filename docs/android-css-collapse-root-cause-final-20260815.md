# تقرير إعادة تحقيق انهيار تصميم Android في سَكِينَة

## النتيجة التنفيذية

بعد إعادة قراءة ملف القواعد الاثنتي عشرة وملفي **CRITICAL-CSS-Import-Order-Root-Cause.md** و**CRITICAL-No-Tailwind-Downgrade-Root-Cause.md**، أُعيد التحقيق على نسخة المشروع الكاملة من GitHub بدل الاعتماد على snapshot ناقص.

السبب الجذري المثبت في النسخة السابقة كان أن ترتيب الاستيرادات في `src/index.css` لم يطابق القاعدة الإلزامية المكتوبة للمشروع. كانت البداية:

```css
@import "tailwindcss";
@import "./styles/player.css";
```

بينما البروتوكول المرفق يطلب أن تأتي ملفات CSS الخارجية أولًا، ثم Tailwind:

```css
@import "./styles/player.css";
@import "tailwindcss";
```

هذا ليس تغييرًا بصريًا؛ إنه تغيير ترتيب cascade وبنية CSS الناتجة فقط.

## الدليل المقارن

تم بناء baseline من المصدر السابق، ثم تغيير ترتيب السطرين فقط وإعادة البناء في تجربة A/B مضبوطة.

| المؤشر | baseline السابق | بعد تطبيق الترتيب الإلزامي |
|---|---:|---:|
| حجم CSS | 142,115 بايت | 142,114 بايت |
| `h-5.5` | موجود | موجود |
| `z-45` | موجود | موجود |
| `--color-quranify` | 13 | 13 |
| `--spacing` | 288 | 288 |
| `@property` | 70 | 70 |
| `color-mix` | 161 | 161 |
| `oklch` | 20 | 20 |

الفرق المهم ليس فقدان Tailwind أو تخفيض الإصدار؛ كلا البناءين يستخدم **Tailwind 4.1.17** و`@tailwindcss/vite`، وكلاهما يحتوي على utilities الحديثة. الفرق هو موضع تعريف متغيرات التصميم المخصصة بالنسبة إلى طبقات Tailwind، وهو ما يلزم تصحيحه وفق القاعدة #2.

## القواعد التي تم التحقق منها

لم يوجد أي `<style>` block داخل مكونات TSX/JSX. إعداد Vite يستخدم `base: './'` في وضع Android. المشروع يستخدم Tailwind 4.1.17، ولم يحدث أي تخفيض إلى Tailwind v3. يحتوي المشروع على `tailwind.config.js` مع safelist، وCSS النهائي يحوي utilities الديناميكية المطلوبة. لم توجد `safe-area-inset` في CSS النهائي مع استخدام Immersive Mode.

كما أن APK الجديد يحتوي على inline splash في `index.html`، ومراجع script وCSS نسبية، وملف CSS بحجم 142,114 بايت يبدأ فعليًا بطبقة Tailwind، وليس ملفًا فارغًا أو ملفًا أقل من 5 KB.

## ما تم تغييره

تم تغيير ترتيب سطري `@import` في `src/index.css` فقط بالنسبة إلى السبب الجديد. بقيت الألوان، الأبعاد، التخطيط، أسماء الكلاسات، الحركات، الخطوط، والأيقونات دون تعديل. الإصلاحات السابقة الخاصة بمسارات الأصول و`BASE_URL` موجودة ضمن تاريخ المشروع، ولم تُحذف.

## البناء والتحقق

نجح `npm run build:android`، ونجح `npx cap sync android`، ونجح `./gradlew assembleDebug --no-daemon --max-workers=1` بعد تجهيز Android SDK وJDK 21 في بيئة البناء. كما فُحص APK مباشرةً بعد البناء.

| عنصر التحقق | النتيجة |
|---|---|
| CSS داخل APK | 142,114 بايت |
| `h-5.5` و`z-45` | موجودان |
| `bg-quranify` ومتغيرات التصميم | موجودة |
| `@property` و`color-mix` و`oklch` | موجودة |
| `safe-area-inset` | صفر نتائج |
| inline splash | موجود، 5 مواضع في HTML المضمن |
| مراجع script/CSS | نسبية داخل APK |
| معاينة المتصفح بعد الإصلاح | الشاشة الرئيسية ظهرت كاملة |
| Console في المعاينة | لا توجد رسائل |

المعاينة ليست بديلًا عن اختبار الهاتف الحقيقي. لذلك لا أصف النتيجة بأنها اعتماد نهائي على كل أجهزة Android قبل أن يثبت المستخدم شكل APK الجديد على هاتفه الفعلي.

## ملاحظة الاختبار الحقيقي

لا يوجد في بيئة التنفيذ جهاز Android فعلي متصل أو log صادر من WebView الخاص به. إذا ظلت النسخة الجديدة «سايحة» على الهاتف، فسيكون الدليل الحاسم التالي هو **لقطة شاشة APK نفسه أو logcat/Chrome WebView console**؛ عندها يمكن تحديد هل المتبقي متعلق بإصدار Android System WebView أو native window rendering، بدل إعادة تغيير CSS عشوائيًا.
